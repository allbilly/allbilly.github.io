Why Step 3 really needs 4D

This version fixes the address model. Step 2 packs each mct × kct tile into a contiguous MemTile region. Step 3 must then visit s-wide strips inside each packed kct tile. That creates four independent nested indices.

1. ShimTile MM2S — 3D

Read one mct × K row-major DRAM tile as a sequence of mct × kmt slabs. Three indices are enough: slab, row, element-in-slab.

slab q0
row i0
inside kmt j0
DRAM addr0
for q in K/kmt
 for i in mct
  for j in kmt
   addr = i·K + q·kmt + j

2. MemTile S2MM — 3D, and this changes the physical layout

The incoming mct × kmt slab is written as consecutive mct × kct blocks. This tile-major packing is the fact Step 3 must respect.

Incoming logical tile

Physical MemTile after S2MM

row i0
kct block b0
inside kct j0
dst physical @0
src = i·kmt + b·kct + j
dst = b·(mct·kct) + i·kct + j
After this step, block b=0 occupies one contiguous region, then block b=1, etc. Step 3 is therefore not reading a plain row-major mct × kmt matrix.

3. MemTile MM2S — the actual 4D proof

The required stream takes every s-wide strip down all mct rows, then moves to the next strip inside the same kct tile, and only after that moves to the next packed kct tile.

A. Physical MemTile addresses produced by Step 2

Cell text is physical address. Small text is the logical matrix coordinate. A whole mct × kct block is contiguous before the next block starts.

B. Required four nested loops

for b  // which packed kct tile inside kmt
for u  // which s-wide strip inside kct
for i  // row inside mct
for v  // element inside s strip
b: kct tile0extent kmt/kct
u: s-strip0extent kct/s
i: row0extent mct
v: in-strip0extent s
addr = b·(mct·kct) + u·s + i·kct + v
4D sizes = [kmt/kct, kct/s, mct, s]
4D strides = [mct·kct, s, kct, 1]

C. The shortest direct proof: strip bases

Try to collapse (b,u) into one 3D counter q.
3D would need: strip_base(q) = base + q·constant_stride
This is the missing fourth dimension. A 3D descriptor can keep i and v, but then it has only one counter left for both “which strip inside kct” and “which kct tile inside kmt”. Those two cannot be merged because their physical jumps are different.

4. CompTile S2MM — back to 3D

For one mct × kct transfer, Step 3 has already made each s-strip contiguous in the stream. Now r rows can be linearized with that strip into z = 0..r·s−1. Only three indices remain: strip-column, microtile-row group, and r·s.

Incoming stream for one kct tile

Pre-tiled CompTile memory

strip u0
microtile row g0
linear z = r·s0
dst @0
for u in kct/s
 for g in mct/r
  for z in r·s

dst = g·(kct/s)·(r·s) + u·(r·s) + z
The important point is not that the tensor “became 3D”. Step 3 already performed the boundary that required distinguishing b from u. Step 4 works on one kct tile at a time, so b is no longer part of this BD.

Precise claim: this proves why the Step-3 access sequence cannot be represented by one 3D affine DMA BD for the non-degenerate case kmt > kct > s. You could still avoid a 4D BD by using multiple 3D BDs, pre-tiling differently, or doing extra software/core shuffles.
