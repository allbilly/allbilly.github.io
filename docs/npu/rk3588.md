# RK3588 NPU

This page collects notes from the [allbilly/rk3588
README](https://github.com/allbilly/rk3588/blob/main/README.md), a pure-Python
project for running operations on the RK3588 NPU through register programming.
It does not use RKNN or a compiler.

## Architecture

The NPU is organized as a pipeline. CNA handles convolution input and weights,
CORE performs MAC-array accumulation, DPU handles output and elementwise
processing, and PPU handles pooling. PC controls operation enable, while RDMA
feeds elementwise data in parallel.

```text
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│   CNA   │───▶│  CORE   │───▶│   DPU   │───▶│   PPU   │───▶│   PC    │
│ Conv    │    │ Compute │    │ Output  │    │ Pooling │    │ Control │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
                    ▲
                    │
                 RDMA
```

The programming model is hierarchical: multiple submits contain multiple
tasks, and each task can contain multiple operations. A task can fuse work such
as convolution, elementwise operations, batch normalization, bias shift, ReLU
and pooling.

## Task configuration

The main enable-mask values are:

| Block | Mask |
| --- | ---: |
| PPU RDMA | `0x40` |
| PPU | `0x20` |
| DPU | `0x10` |
| CORE | `0x08` |
| CNA | `0x04` |
| PC | `0x01` |

Typical combinations from the project are:

```text
CONV             0x0d = CORE | CNA | PC
GEMM/elementwise 0x18 = DPU  | CORE
POOL             0x60 = PPU_RDMA | PPU
```

The task interrupt mask is commonly `0xc00` or `0x300`, and the operation index
used by the examples is `1` for convolution and `4` for GEMM.

## Quick start

The examples are self-contained Python programs. On an Orange Pi Ubuntu image
with the vendor RKNPU driver installed:

```bash
pip install numpy
python examples/elementwise.py
python examples/gemm.py
python examples/conv.py
python examples/conv_gemm.py
```

On mainline Armbian with the ROCKET driver:

```bash
python examples/kernel6_18/conv.py
python experimental/kernel6_18/elementwise.py
python experimental/kernel6_18/gemm.py
python experimental/kernel6_18/pool.py
```

The project reports testing on an Orange Pi 5 16 GB, Orange Pi Ubuntu 1.2.2
with Linux 6.1.99, and Armbian Ubuntu 24.04 with a 6.18 Rockchip kernel.

## PC chaining and multicore

PC chaining allows multiple operations to run within one submit, reducing
submit overhead. The project demonstrates this in the GEMM, convolution and
pool examples. Large matrix multiplications can be split along the N dimension
and chained into one submit.

The RK3588 has three NPU cores. Different operations—or partitions of a GEMM—
can run on separate cores. Multicore support is still marked work in progress
in the source project; its current example is:

```bash
python experimental/pool_multicore.py
```

## Matmul through convolution

The RK3588 NPU is NVDLA-based and designed around convolution. The project maps
matrix multiplication onto a 3D `1×1` convolution:

```text
C(M,N) = A(M,K) × B(K,N)

Input feature map A:  H=M, W=1, C=K
Convolution kernel B: N kernels, R=1, S=1, C=K
Output feature map C: H=M, W=1, C=N
```

Each input row `A[m, :]` becomes a feature-map position, each output column
`B[:, n]` becomes a convolution kernel, and the resulting output satisfies:

```text
C[m, n] = Σ A[m, k] · B[k, n]
```

## Register notes

The project identifies these common target blocks:

| Target | Block |
| ---: | --- |
| `0x0201` | CNA / convolution front-end |
| `0x0801` | CORE / MAC array |
| `0x1001` | DPU / output and elementwise |
| `0x2001` | RDMA |
| `0x0081` | PC / operation enable |

For detailed register fields, examples and driver comparisons, see the
[upstream README](https://github.com/allbilly/rk3588/blob/main/README.md) and
the project’s `experimental/rockchip.py` implementation.
